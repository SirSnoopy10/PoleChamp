## 1. Organizacja testów w kodzie

| Moduł | Lokalizacja testów | Środowisko | Uwagi |
|---|---|---|---|
| `@polechamp/scoring` | `packages/scoring/test/**` | Vitest (Node 26) + Jest (`apps/mobile/test/parity`) | 100% gałęzi; ten sam zestaw przypadków referencyjnych w obu środowiskach (TC-SCORING-031) |
| `@polechamp/contracts` | `packages/contracts/test/**` | Vitest | test dokumentacyjny katalogu błędów czyta `docs/01-architecture/03-api.md` |
| `@polechamp/i18n`, `@polechamp/tokens` | `packages/*/test/**` | Vitest | kontrast liczony wzorem WCAG 2.x |
| Outbox i SyncEngine | `apps/mobile/src/sync/**/*.test.ts` | Jest + better-sqlite3 (te same migracje co `expo-sqlite`) | zegar sterowany, sieć mockowana (`msw` dla `fetch`) |
| Logika stanu i hooki | `apps/mobile/src/**/model/*.test.ts` | Jest | czyste funkcje i store'y Zustand |
| Komponenty UI | `apps/mobile/src/ui/**/*.test.tsx` | Jest + RNTL | zapytania po rolach i etykietach a11y (wymusza NFR-206); zrzuty wizualne – [06](06-testy-zgodnosci-z-designem.md) |
