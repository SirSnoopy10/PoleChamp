## 1. Cel i niezmienniki

Każdy przypadek sprawdza co najmniej jeden z niezmienników:

| ID | Niezmiennik | Jak sprawdzamy |
|---|---|---|
| N1 | Ocena zatwierdzona (toast) nigdy nie ginie | porównanie liczby arkuszy na tablecie i serwerze + `rejected_submission` |
| N2 | Ocena nie jest przyjęta dwa razy | `score_sheet` UNIQUE (start, sędzia), liczba rewizji = liczba świadomych zatwierdzeń |
| N3 | Wynik ostateczny odpowiada stanowi w chwili blokady | `final_results_hash` przed i po spóźnionych mutacjach |
| N4 | Czas urządzenia nie wpływa na przyjęcie ani kolejność | testy z zegarem ±24 h |
| N5 | Sędzia nie widzi cudzych ocen także po synchronizacji | zrzut bazy SQLite i zapytania UI |

## 2. Techniki i narzędzia

- **Sieć:** tryb samolotowy (Maestro + `adb shell cmd connectivity airplane-mode`), `adb shell svc wifi disable`, Network Link Conditioner (iOS), **toxiproxy** między API a klientem testowym (zerwanie po N bajtach, opóźnienie, utrata pakietów), `tc netem` na staging dla symulacji 30% utraty.
- **Proces:** `adb shell am force-stop` / `kill -9` w pętli (100 iteracji) z losowym opóźnieniem po toaście; iOS – `xcrun simctl terminate` (próbka 20 iteracji) oraz ręcznie na iPadzie.
- **Zasilanie:** procedura ręczna (twarde wyłączenie) na tabletach referencyjnych – 10 powtórzeń.
- **Zegar:** zmiana czasu systemowego urządzenia / emulatora; serwer z zegarem rzeczywistym.
- **Wiele tabletów:** symulator urządzeń w Node (te same kontrakty, ta sama biblioteka outboxu skompilowana dla Node) dla 20 tabletów + 2 fizyczne tablety.
