## 1. Zasady

- **Narzędzie:** Maestro CLI 2.11 – przepływy YAML w `apps/mobile/e2e/maestro/{org,judge,full,sync}`. Selektory: `testID` (konwencja `<ekran>.<element>`, np. `org.tournament.startButton`) oraz teksty wiążące z i18n (weryfikują jednocześnie treść).
- **Środowisko:** staging, build `preview` z flagą `E2E_HELPERS` (endpointy przygotowania stanu: seed fikstury, przesunięcie zegara serwera dla testów wygaśnięć, odczyt kodu e-mail z Mailpit). Flaga jest wyłączona w buildzie i środowisku produkcyjnym (TC-SEC-018).
- **Urządzenia:** nocnie emulatory Android (telefon API 34, tablet API 36) i symulatory iOS (iPhone, iPad); przed wydaniem 4 urządzenia referencyjne ([00 §7](00-strategia-testowania.md#7-urządzenia-referencyjne-nfr-703-i-macierz)).
- **Dwa urządzenia:** scenariusze `FULL` uruchamia orkiestrator ([IMP-457](../04-implementation-plans/11-qa-i-automatyzacja-testow.md)) sterujący równolegle telefonem i tabletem oraz API.
- **Stabilność:** animacje wyłączone w buildzie E2E, czas zamrożony tam, gdzie to możliwe, ponowienie niestabilnego testu maks. 1×.
